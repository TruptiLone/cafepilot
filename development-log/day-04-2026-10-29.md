- `POST /api/v1/sales/projections/usage` and `SalesService.project_usage()`: read-only
  expansion of a hypothetical product mix through recipes and modifiers (reuses the
  existing sale-usage logic; writes nothing). Status `computed | partial | unmapped`.

  services directly. Input/output JSON schemas generated from Pydantic. Each action has
  `produces`, `consumes`, `requires` (any-of groups) and `approval`.

  `order_ref`, rejects wrong units. No real order is placed.

  8 explicit safety edges, cycle check with `graphlib` at build time.

## Task 2 — Planner: query → plan DAG ✅ (mocked; live run pending)

**Built**

- `backend/modules/agent/planner.py`
  - `Plan` / `PlanNode` schema: `status` (`plan | needs_clarification | out_of_scope`),
    goal, assumptions, nodes with `id`, `action`, `args`, `reason`, and `only_if` (the
    condition the owner checks before approving a write). Unique snake_case ids, ≤15 nodes.
  - `build_planning_context()`: café timezone, `as_of`, and a reference snapshot of real
    IDs (active variations, modifiers, ingredients, employees) so the model never invents IDs.
  - Prompt built from the registry on every call (`describe_for_planner()`); `$node.field`
    references for data flow; writes are proposals that wait for approval.
  - `plan_query()`: Meta Model API via the OpenAI SDK, `muse-spark-1.3`, temperature 0;
    tolerant JSON parsing (code fences); every call logged to `business-core/var/llm_calls.jsonl`
    (gitignored), including failures.
- `POST /api/v1/agent/plans` → plan only; nothing is validated or executed yet.
  404 unknown café (before any model call), 422 naive `as_of`, 502 bad model output,
  503 when `MODEL_API_KEY` is missing or blank.
- Settings: `MODEL_API_KEY`, `MODEL_API_BASE_URL`, `PLANNER_MODEL` in `business-core/.env`.
- `scripts/try_planner.py`: one live call with the hero query; saves
  `tests/fixtures/agent/hero_plan_live.json`.
- Fixed the `list_products` action description (it does not return variations).
