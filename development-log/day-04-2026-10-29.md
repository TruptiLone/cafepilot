## Task 1 — Action registry + superset DAG ✅

**Built**

- `POST /api/v1/sales/projections/usage` and `SalesService.project_usage()`: read-only
  expansion of a hypothetical product mix through recipes and modifiers (reuses the
  existing sale-usage logic; writes nothing). Status `computed | partial | unmapped`.
- `backend/modules/agent/registry.py`: 18 actions (13 read, 5 write) wrapping existing
  services directly. Input/output JSON schemas generated from Pydantic. Each action has
  `produces`, `consumes`, `requires` (any-of groups) and `approval`.
  `Action.run()` validates args, calls the service, returns JSON-safe output
  (Decimals as strings). `describe_for_planner()` gives the planner its action list.
- `propose_supplier_order`: simulated, labeled `simulated: true`, deterministic
  `order_ref`, rejects wrong units. No real order is placed.
- `backend/modules/agent/superset.py`: 17 data edges computed from produces/consumes,
  8 explicit safety edges, cycle check with `graphlib` at build time.

**Validated**

- New tests: `tests/test_agent_registry.py` (24), `tests/test_sales_projection_api.py` (4).
- Projection reproduces AF-01: 40 whole + 20 oat lattes → 9,600 mL whole milk,
  4,800 mL oat milk, 1,080 g beans; no sale or movement is written.
- Full suites: backend **190 passed, 3 skipped**; frontend **43 passed**; `tsc` clean.
