# Day 5 — Thu night Oct 29 / Fri Oct 30

Reviews (Gemini, ChatGPT, Perplexity) agreed on one credibility issue: "Done" overclaimed. Approving
a change is not the supplier confirming or the employee agreeing. Plan for the rest of the week:
honest statuses → supplier rejection + replan → staffing math in code → plain-language assumptions →
Today endpoint → rebuild the Genspark screens → receiving (inventory) use case → voice → video.

## Honest status for every change ✅

- New tables (migration `3a82cc11523a`): `purchase_orders` + `purchase_order_lines` (supplier, status
  sent / confirmed / rejected / …, requested and confirmed delivery, packs, pack prices, total,
  `simulated`, source run/step; `received_quantity` ready for receiving), `shift_offers` (pending /
  accepted / declined).
- Simulated suppliers in café policy: **Bay Dairy Co.** (usual; no Sunday deliveries before 9 AM) and
  **Valley Farms** (Sundays from 5:30 AM, ~12% dearer), 1 L cartons with prices. A generic simulated
  supplier is used for cafés without a supplier list.
- Approving an order **sends** it (stable `po_agent_…` id); approving a shift puts it on the schedule
  and **offers** it. The simulator decides when sent and reveals its answer after a few seconds
  (`settle_due`, scoped per café, row-locked); a declined shift is taken off the schedule.
- API: every change has `lifecycle` (Proposed → Approved → Sent/Offered → Confirmed/Accepted or
  Rejected/Declined), `external_status`, an acknowledgement with tone and `next_step`; runs have
  `waiting_on`. Muse's closing line says what is still pending.

## Supplier rejection → Muse replans ✅

- `get_purchase_order` action (reorder_lines = the same quantities); validator accepts
  `"$<get_purchase_order>.reorder_lines"` as a code source for order quantities.
- `POST /agent/runs/{id}/nodes/{node}/replan`: code writes the request from the facts (who said no,
  why, what is still needed and by when) and plans a new run linked to the failed change
  (`parent_run_id`, `parent_node_id`; migration `35c888456e31`). Declined shifts replan the same way.
- Prompt rules 13–14 (replanning). Planner reference data now lists suppliers and their delivery hours.
- Page: lifecycle chips on every change, auto-refresh while waiting, "Find an alternative" /
  "Find someone else", link between the two plans, header "Waiting on …".
