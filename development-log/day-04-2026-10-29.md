## Task 3 — Validator ✅

**Built**

- `backend/modules/agent/validator.py` — `validate_plan(plan, cafe_id)` returns
  `valid`, `issues` (code, node, message), `warnings`, `nodes` (with side effect, approval
  flag, dependencies, level), `edges` (data or safety) and `levels` (parallel groups).
  Checks: registered action; argument names and values against the action's Pydantic
  model (steps with `$` references get name/required checks now, values at execution);
  `$` references point to an existing, different step and the link is allowed by the
  superset; every safety prerequisite is in the plan; same café; no cycles.
  **Safety edges are added by the validator itself**, so a write is ordered after its
  prerequisites even when the model writes no references (as in the live run).
  Duplicate identical steps are a warning, not an error.
- `backend/modules/agent/service.py` — `plan_and_validate()`: if the plan is rejected or
  unparseable, the model gets its previous answer plus the reasons and one retry.
  Clarification questions return immediately.
- `POST /api/v1/agent/plans` now returns `validation` and `attempts` alongside the plan.
  A plan still rejected after the retry comes back with `valid: false` and readable reasons.

**Validated**

- `tests/test_agent_validator.py` (24): mock and **live** hero plans valid with reads at
  level 0 and writes after; each rejection code; any-of prerequisite groups; back-references
  blocked by the superset; cycle check proven as a backstop with a permissive rulebook;

## Task 4 — Executor ✅

**Built**

- Tables (`alembic 535a8fcd0233`, round-trip tested): `agent_plan_runs` (query, goal,
  assumptions, status, as_of, model, edges, levels), `agent_node_runs` (one per step:
  args, resolved args, status, result, error, idempotency key, replay_of, timings),
  `agent_approvals` (decision, who, channel web/voice/glasses/api, note, when).
- `backend/modules/agent/executor.py`
  - `create_run` stores a validated plan; `execute` runs every ready step in level order.
  - `$step.path` arguments resolved from upstream results, then re-validated.
  - Writes stop at `awaiting_approval`; nothing waits in memory.
  - `decide` / `decide_all` record the decision and resume; repeats are no-ops.
  - Replay protection: a write whose action + resolved args already succeeded in an
    earlier run is marked done with `replay_of` instead of running again.
  - Failures and rejections are recorded on the step; downstream steps are skipped.
  - Run status: `running | awaiting_approval | completed | completed_with_issues`.
- API: `POST /agent/runs` (plan → validate → run reads), `GET /agent/runs`,
  `GET /agent/runs/{id}`, `POST /agent/runs/{id}/nodes/{node}/decision`,
  `POST /agent/runs/{id}/decision` (approve/reject all waiting).

**Validated**

- `tests/test_agent_executor.py` (15): reads complete; write waits and writes nothing;
  approval writes exactly once (double click safe); execute twice = no new work;
  replaying the same plan never schedules a second shift; reject skips dependents;
  `$count.count_id` resolved from an approved write; failed step and bad reference
  recorded without crashing the run; reads cannot be "approved"; full API cycle.
- Live plan replayed on seeded CAFE001 (rolled back): 5 reads done, shift waits,
  approval completes the run.
- Full suites: backend **246 passed, 3 skipped**; frontend **43 passed**; `tsc` clean.
